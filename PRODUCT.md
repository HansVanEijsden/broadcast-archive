# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Existing WordPress plugin (PHP 8.2+, no Composer dependencies) with a vanilla JavaScript front end and a single CSS file. No build step: the plugin must be installable by copying a folder into `wp-content/plugins`. WordPress 7.x, classic shortcode rendering.

## Users

- **Listeners** of a regional Dutch radio station, mostly on a phone, who missed a programme and want to find and play it. They arrive from a menu item, not from search; they know roughly when the programme aired, often not its exact name.
- **Station editors / webmasters** who install and configure the plugin for one station (Salland1 now, 1Zwolle next) and expect it to keep working without maintenance.

## Product Purpose

Turn a station's existing podcast archive feed into a "listen again" page on the station website: find a broadcast by day, programme or title, play it inline or in a persistent player, and download it. Success means a listener can start the right broadcast within seconds, and the page keeps working unattended for months.

## Positioning

A deliberately thin bridge between a plain RSS podcast feed and a themed WordPress page. It owns no archive of its own, works with any station's feed and branding, and is designed for aggressively cached WordPress stacks: public endpoints carry no nonces and no per-visitor state, so a page cached for weeks still works for logged-out visitors.

## Operating Context

- salland1.nl runs WordPress 7.1 on PHP 8.5 inside Docker, Newspaper (TagDiv) theme.
- Full-page cache is nginx `srcache` backed by Redis with **no TTL**: cached HTML lives until Redis evicts it or WordPress purges it. Logged-in users bypass the cache; logged-out visitors get the cached copy.
- The archive is generated by `dir2cast` at `archive.<station>.nl`, exposing an RSS 2.0 + iTunes feed (`podcast.php`) and hourly `.m4a` files with matching `.jpg` covers.
- The Salland1 feed holds ~168 hourly items (one week), ~350 KB, newest first. Titles look like `Programme - 25 November 2026 (15:00 - 16:00)`.
- Episodes are hour-long talk/music programmes; listeners often start mid-programme.

## Capabilities and Constraints

- List episodes newest first, grouped per day, with programme, time slot, duration, cover and presenter.
- Search over titles, programmes and descriptions; filter by programme and by day.
- Inline playback plus one persistent player that survives filtering, paging and scrolling; remembers the last position per episode in the browser.
- Download an episode through the site with a friendly filename.
- Show the playlist / description as readable text.
- Station-neutral configuration: feed URL, station name, accent colour, locale, timezone, page size, cache lifetime, optional download host allowlist.
- English source strings; Dutch interface on Dutch sites through standard WordPress translations.
- Public data endpoints must work for anonymous visitors and must never embed a nonce or user-specific value in cached HTML.
- No JavaScript framework, no build step, no external font or icon CDN.
- Must degrade gracefully when the archive is unreachable: serve the last known good feed, then a clear error state with retry.

## Brand Commitments

- Salland1 house colour is red `#e50526`; the site is otherwise light, editorial and utilitarian (Newspaper theme, Roboto headings).
- The plugin should look native to the host theme, not like an embedded third-party widget.
- Interface text on salland1.nl is Dutch; the repository and source strings are English.

## Evidence on Hand

- Live page: https://www.salland1.nl/uitzending-gemist/
- Live feed: https://archive.salland1.nl/podcast.php (real titles, descriptions, playlist lines, covers).
- Legacy plugin source: `legacy-orig/` in this repository (ChatGPT-built v1.0.3, being replaced).

## Product Principles

1. **Reliability beats cleverness.** A listener must never meet a security or JSON error because a cache aged; public reads need no nonce.
2. **The page cache is part of the architecture**, not an obstacle. Everything the plugin prints must be identical for every logged-out visitor.
3. **Listening outlives navigation.** Playback continues while the listener searches, filters and pages.
4. **The station's brand wins.** Colour, locale and name are configuration; the plugin supplies structure, not identity.
5. **Work unattended.** Failures are absorbed (stale feed, image error, blocked request) and explained in the listener's language.

## Accessibility & Inclusion

- WCAG 2.2 AA target: keyboard operability for every control, visible focus, 4.5:1 text contrast, labelled form controls, live-region status messages, reduced-motion support.
- Works at 320 px width and at 200% text zoom without clipping.
- No reliance on colour alone to convey state.
